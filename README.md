# NetAtlas

Личная система аудита локальной сети: автоматическая карта топологии, полный аудит железа и софта, измерение качества сети, проверка безопасности и ИИ-рекомендации по улучшению и модернизации.

> Рабочее название. Проект строго для личного использования, не для продажи и не для внешних пользователей.

## Зачем

Одна точка управления небольшой сетью на Windows-компьютерах:

- увидеть, что в сети есть и как оно соединено (карта, а не таблица);
- знать состояние каждого компьютера: железо, диски, драйверы, программы;
- видеть качество сети: задержки, потери, скорость, узкие места;
- находить проблемы безопасности внутри сети;
- получать понятные рекомендации по обновлению и модернизации;
- безопасно чинить типовые проблемы (принтер не виден, устарел драйвер) проверенными скриптами.

## Главные принципы

1. **ИИ не имеет доступа к сети и компьютерам.** Он получает очищенный текстовый отчёт и возвращает только текст-рекомендацию. Мост между зонами только человек.
2. **Ничего не выполняется без конвейера:** черновик скрипта → статическая проверка → тест на виртуальной машине (Hyper-V) → подпись владельца → один компьютер → замер «до/после» → группа.
3. **Агент выполняет только подписанное.** Сервер технически не отправляет скрипт без статуса «протестирован» и подписи.
4. **Агент подключается к серверу сам** (исходящее соединение, mTLS), входящие порты на компьютерах не открываются.
5. **Факты считает код, а не ИИ.** Состояние железа, оценка безопасности, прогнозы по дискам вычисляются правилами. ИИ только формулирует и приоритизирует.
6. **Прозрачность для сотрудников.** Нет перехвата нажатий клавиш, содержимого переписки и скриншотов. Сотрудники уведомлены о наблюдении, на ПК виден значок.

## Как работает

**Фаза 0. Сканирование без агентов** с админского компьютера: ARP/ping по подсетям, Nmap, DHCP-аренды роутера, SNMP на коммутаторах (таблица MAC по портам, LLDP/CDP), список Wi‑Fi клиентов, имена через NetBIOS/mDNS/SSDP, производитель по MAC. Результат: первая топология.

**Фаза 1. Агенты** ставятся на компьютеры и «повышают» найденные узлы до управляемых: железо, диски, ПО, активность, исполнение проверенных действий.

**Гостевые и прочие устройства без агента** остаются в карте как класс «Без агента»: видны IP, MAC, производитель, порт или точка доступа, присутствие и трафик. Для новых неизвестных устройств есть оповещение и выбор класса (моё, гость, известное без агента, неизвестное).

## Состав системы

| Компонент | Задача |
|---|---|
| Агент (Windows) | Сбор данных, измерения связи, выполнение подписанных заданий |
| Сервер | Приём данных, хранение, подпись заданий, API, веб-интерфейс |
| Сканер | Безагентное обнаружение и построение топологии |
| Движок правил | Оценки, прогнозы, поиск проблем |
| Сборщик отчётов | Структурированный и очищенный отчёт для ИИ |
| Конвейер скриптов | Проверка, тест на ВМ, подпись, раскатка, откат |
| Журнал аудита | Кто, когда, что и на каком компьютере запустил |

## Экраны (макеты в `design/`)

1. Карта сети: ручное добавление элементов, именование, проверка, связи, вкладка устройства по клику на значок (обзор, диски, сеть, пользователь, правка), значки по типам устройств
2. Карточка компьютера: железо, драйверы, план модернизации
3. Диски: заполнение, здоровье, прогноз
4. Качество сети: матрица связи, скорость интернета, узкие места
5. Безопасность: оценка и замечания
6. Активность сотрудников: время, приложения, домены сайтов
7. Отчёт для ИИ: единая форма, очистка данных, ответ
8. Скрипты и тесты: конвейер, подпись, журнал

Планируются: мастер первого сканирования, «Найденные устройства» (классификация), вид узла «Без агента» и группа «Гостевая сеть».

## Предполагаемый стек

Рекомендация, итоговый выбор остаётся за этапом проектирования.

- Агент и сервер: Go (статический бинарь, служба Windows)
- Хранилище: SQLite (для масштаба личной сети достаточно)
- Веб-интерфейс: TypeScript, граф на Cytoscape.js
- Тестовая среда: Hyper-V (снимки и PowerShell Direct)
- ИИ-слой: отдельный модуль «текст в текст», облачный API или локальная модель

## Дорожная карта

0. Безагентное сканирование и карта
1. Агент и сервер: безопасный канал, инвентарь железа и ПО
2. Измерения сети и качество связи
3. Каталог проверенных действий, подпись, конвейер тестов
4. Аудит безопасности
5. Активность сотрудников
6. Отчёты и ИИ-рекомендации

Порядок важен: ИИ полезен только когда уже есть хорошие данные и надёжный механизм исполнения.
