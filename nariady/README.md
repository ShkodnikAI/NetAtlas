# Наряды

Наряд это структурированное задание для исполняющего агента. Исполняет один агент, проверяет и принимает аудитор (Claude), решение за владельцем.

## Процесс

1. Наряд в статусе `draft` показывается владельцу вместе с оценкой риска.
2. Владелец подтверждает (`approved`). Без подтверждения работа не начинается.
3. Исполнитель работает в ветке `nr-XXX`, прямых коммитов в `main` нет.
4. Перед PR: `go vet`, тесты, линтер, проверка списка изменённых файлов на неприкасаемые зоны.
5. Аудитор проверяет PR по критериям приёмки и инвариантам из [docs/DECISIONS.md](../docs/DECISIONS.md). Красные тесты или нарушение инварианта означают возврат.
6. Для среднего и высокого риска нужно второе подтверждение владельца перед слиянием.
7. Слияние выполняет владелец. После слияния статус `executed`.
8. Откат: `git revert` слитого PR и запись в журнале. Force push запрещён.

Развёртывание на реальных компьютерах владельца только после отдельного подтверждения и сначала на одной машине.

## Классификация риска

| Риск | Что затрагивает |
|---|---|
| low | Документы, макеты, структура репозитория, CI |
| medium | Сканер, хранилище, правила, веб-интерфейс, измерения, чтение данных |
| high | Агент, сервер авторизации, PKI и подписи, конвейер скриптов, сбор активности, отчёты для ИИ |

Любой наряд, затрагивающий неприкасаемую зону, считается high.

## Неприкасаемые зоны

Менять можно только нарядом, который владеет зоной, с высоким риском и двойным подтверждением:

- `server/audit/`: журнал аудита (только добавление, без удаления и правки записей)
- `pipeline/gate/`: проверка статуса «протестирован» и подписи перед отправкой задания
- `agent/verify/`: проверка подписи задания на агенте
- `pki/` (код), закрытые ключи и сертификаты в репозиторий не попадают никогда
- `docs/DECISIONS.md`: инварианты
- `nariady/README.md`: правила процесса

## Антипаттерны

- Выполнение действий на компьютерах без подписи и подтверждения
- Доступ ИИ-модуля к сети, агентам, ключам или репозиторию скриптов
- Секреты, токены и пароли в коде, логах и отчётах
- Сбор нажатий клавиш, содержимого переписки и скриншотов
- Коммит без тестов, force push, прямой push в `main`
- Журнал аудита с возможностью удаления
- Сканирование за пределами заданных подсетей
