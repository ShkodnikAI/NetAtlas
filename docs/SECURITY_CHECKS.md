# Безопасность: проверки, веса, основания (NR-010)

Документ — источник правды по проверкам безопасности. Каждая проверка **только читает** состояние машины: ничего не включает, не отключает, не пишет в реестр, не запускает активных проб. Это проверяется тестом «только чтение» (`agent/checks/read_only_test.go`): статический разбор всех встроенных сценариев агента, запрещённые глаголы (`Set-*`, `Enable-*`, `Disable-*`, `New-*`, `Remove-*`, `Invoke-*` и другие) ломают сборку тестов; белый список — один член, `Start-Sleep` (пауза в сценарии замеров), обоснование — в самом тесте.

## Отчёт проверок

Агент запускает встроенные сценарии PowerShell и отправляет результат на `POST /agent/v1/security` (конверт `kind=security`, `schema_ver=1`, тело ≤ 256 КБ). Каждая проверка независима: ошибка одной не роняет отчёт.

Три состояния проверки — и «не определено» **не равно** «безопасно»:

| Статус | Значение | Влияние на оценку |
|--------|----------|-------------------|
| `pass` | проверка выполнена, замечаний нет | нет |
| `fail` | проверка выполнена, найдено замечание | вес правила вычитается |
| `unknown` | проверка не состоялась: нет командлета, отказ в доступе, пустой или неразборчивый вывод | **нет** (но считается в сводке) |

`unknown` никогда не превращается в «безопасно»: если командлета нет (например, BitLocker на Home-редакции), система фиксирует «не определено», и счётчик таких проверок виден в сводке экрана.

## Проверки агентов (Windows)

| Проверка | Как (только чтение) | Что фиксирует | Правило |
|----------|---------------------|---------------|---------|
| `smbv1` | `Get-SmbServerConfiguration` → `EnableSMB1Protocol` | SMBv1 включён | `sec_smbv1_enabled` |
| `bitlocker` | `Get-BitLockerVolume` → статус защиты томов | том без шифрования | `sec_bitlocker_off` |
| `rdp_nla` | реестр `HKLM\...\Terminal Server` (`fDenyTSConnections`), `...\RDP-Tcp` (`UserAuthentication`) — читается, не пишется | RDP включён без NLA | `sec_rdp_no_nla` |
| `firewall` | `Get-NetFirewallProfile` → `Enabled` по профилям | профиль выключен | `sec_firewall_off` |
| `ports` | `Get-NetTCPConnection -State Listen` + имя процесса | **данные без суждения**: список слушающих портов виден в карточке компьютера, вес не начисляется | — |
| `defender` | `Get-MpComputerStatus` → защита в реальном времени | защита отключена | `sec_defender_off` |

Из инвентаря агента (отдельный сбор не нужен):

| Проверка | Источник | Правило |
|----------|----------|---------|
| Версия и поддержка ОС | инвентарь (`os.caption`, `os.build_number`) + таблица `rules/data/os_lifecycle.json` — правило NR-009 `os_out_of_support` переиспользуется, логика сроков одна | `os_out_of_support` |
| Устаревшее ПО | инвентарь (`programs`) против таблицы `rules/data/software_min_versions.json` | `sec_software_outdated` |

## Сетевые устройства (без агентов)

Основание — только то, что **уже известно сканеру**: устройство ответило на SNMP-опрос, который владелец сам настроил в мастере сканирования. Новых активных проб нет.

| Наблюдение | Как получено | Правило |
|------------|--------------|---------|
| SNMPv1/v2c включён | признак из метода опроса: цель ответила на опрос по v2c (учётка `NETATLAS_SNMP_*` с community) | `sec_snmp_v2c_enabled` |
| Интерфейс управления доступен по сети | устройство ответило на SNMP-опрос (порт UDP 161) | `sec_snmp_admin_open` |

Наблюдения сохраняются как `observations` устройства (`snmp`, `snmp_v2c`) при каждом скане с SNMP-целями; экран показывает свежие записи.

## Веса и оценка

Оценка компьютера: **100 − сумма весов его активных замечаний**, не меньше 0. Общая оценка на экране: **среднее по компьютерам с данными** (округление вниз). Без данных оценка — `null`, а не 100: «нет данных» не превращается в «всё безопасно». Сетевые замечания показываются списком и в оценку компьютеров не входят (у них нет собственной конфигурации Windows).

Веса — `rules/data/security_weights.json` (переопределяется через `--rules-dir`):

| Правило | Серьёзность | Вес |
|---------|-------------|-----|
| `sec_smbv1_enabled` | critical | 25 |
| `sec_rdp_no_nla` | critical | 20 |
| `sec_firewall_off` | critical | 20 |
| `os_out_of_support` | critical | 20 |
| `sec_bitlocker_off` | warning | 15 |
| `sec_defender_off` | warning | 15 |
| `sec_software_outdated` | warning | 10 |
| `sec_snmp_v2c_enabled` | warning | 10 |
| `sec_snmp_admin_open` | info | 3 |

Оценка **воспроизводима**: один и тот же вход даёт один и тот же результат (тест `rules/security`: сортировка замечаний по правилу, факту и источнику; JSON вывода совпадает байт в байт). Порог «ровно минимум» — не замечание (тесты на границы версий ПО).

## Основания

Номера рекомендаций не выдумываются: если точный номер не подтверждён, даётся название раздела и страницы, номер не пишется.

| Правило | Основание (публичный источник) |
|---------|-------------------------------|
| `sec_smbv1_enabled` | CIS Microsoft Windows Benchmark, раздел «SMB Server» (SMBv1 Server and Client components); Microsoft Learn: «SMBv1 is not installed by default in Windows 10 Fall Creators Update and Windows Server, version 1709» |
| `sec_bitlocker_off` | CIS Microsoft Windows Benchmark, раздел «BitLocker Drive Encryption»; Microsoft Learn: «BitLocker overview» |
| `sec_rdp_no_nla` | CIS Microsoft Windows Benchmark, раздел «Remote Desktop Services» (Network Level Authentication); Microsoft Learn: страница «Network Level Authentication» |
| `sec_firewall_off` | CIS Microsoft Windows Benchmark, раздел «Windows Firewall» (Firewall state: Domain/Private/Public); Microsoft Learn: «Best practices for Windows Firewall» |
| `sec_defender_off` | CIS Microsoft Windows Benchmark, раздел «Microsoft Defender Antivirus»; Microsoft Learn: «Microsoft Defender Antivirus on Windows» |
| `os_out_of_support` | жизненный цикл ОС Microsoft (страницы lifecycle Windows 10 Home and Pro, Windows 11); таблица `rules/data/os_lifecycle.json` |
| `sec_software_outdated` | локальная таблица владельца `rules/data/software_min_versions.json` (`source_url` у каждой строки); интеграция с NVD — отдельным нарядом |
| `sec_snmp_v2c_enabled`, `sec_snmp_admin_open` | CIS Network Devices Benchmark, раздел «SNMP» (community-строки передаются открытым текстом); признак из метода опроса сканера |

## Таблица минимальных версий ПО

`rules/data/software_min_versions.json` — короткая, заполняется владельцем: строка — семейство программ (совпадение по подстроке имени без учёта регистра), `min_version` — минимально допустимая версия, `source_url` — источник, `verified` — подтверждена ли строка (записи с `verified=false` дают замечание не серьёзнее info). Сравнение версий числовое по сегментам через точку; нечисловые хвосты (`24.0.0 (сборка 3)`) отбрасываются; у программы без версии суждения нет.

## Чего в наряде нет и почему

- **Подбора паролей и активных атак нет**, «устройства с заводскими паролями» из старой заготовки **не делаются**: для этого пришлось бы пробовать пароли на устройствах — это активные попытки аутентификации, запрещённые правилом «только чтение». Записано как отказ.
- **NVD не подключён**: поиск известных уязвимостей по списку ПО — отдельный наряд; сейчас работает локальная таблица минимальных версий.
- **Автозапуск гостевой учётной записи и пустые пароли политикой не проверяются**: нужны изменения прав (политики безопасности), это не чтение.
- **Исправлений нет**: экран показывает рекомендацию текстом; исправления проходят общий конвейер (рекомендация, скрипт, тест на ВМ, подпись — `docs/DECISIONS.md`).

## Проверка Windows

Сборщики работают без прав администратора, где это возможно; командлет, требующий прав, даёт `unknown` — это штатное состояние, а не ошибка сборщиков. На `windows-latest` тест `TestRealSecurityChecksOnWindows` запускает реальный сбор (`BuildReport` на живой машине) и проверяет каркас: все шесть проверок вернули валидный статус, ошибки — только в журнале теста.
