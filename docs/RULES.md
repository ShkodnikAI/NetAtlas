# Правила, замечания и прогноз дисков (NR-009)

Движок правил превращает инвентарь агентов в понятные замечания и
прогноз заполнения дисков. Без ИИ: пороги и тексты рекомендаций
заданы заранее.

## Как работают правила

Правила — JSON (`rules/data/rules.json`), встроены в бинарь и
переопределяются каталогом `--rules-dir` без перекомпиляции. Каждое
правило содержит:

| Поле | Смысл |
|------|-------|
| `id` | имя правила (совпадает с веткой вычислителя) |
| `severity` | `critical` (вес 100), `warning` (40), `info` (10) |
| `advice` | готовый текст рекомендации, не генерируется |
| `source` | поля инвентаря, из которых берётся факт; правило без `source` загрузчик отвергает |
| `params` | пороги (границы проверены тестами «ровно порог / ниже / выше») |

Замечание (finding) содержит `fact` (что наблюдается), `threshold`
(порог), `source` (поле инвентаря и время сбора), `severity`,
`advice` и `priority`.

**Приоритет** = вес серьёзности × срочность (urgency, 1…10):

| Правило | Срочность |
|---------|-----------|
| ОС вне поддержки | 10 |
| ОС кончается: ≤30 дней / ≤90 / ≤180 | 8 / 5 / 3 |
| Свободно на томе C | `10 − свободно%` |
| Износ SSD | `износ / 10` |
| Температура диска | `°C / 10` |
| Обновления не ставились | `дней / 10` |
| ОЗУ ниже порога | 4 |
| Поколение CPU | 2 |
| Драйверы старше 3 лет | 1 |

Строки справочных таблиц с `"verified": false` не дают замечаний
серьёзнее `info`.

## Список правил по умолчанию

| id | Порог | Серьёзность |
|----|-------|-------------|
| `ram_low` | ОЗУ < 8 ГБ (свободные слоты из инвентаря v1 не видны — в совете) | warning |
| `ssd_wear_high` | износ SSD > 80 % | warning |
| `disk_temp_high` | температура > 70 °C | warning |
| `os_out_of_support` | вне поддержки или кончается ≤180 дней (таблица) | critical / warning |
| `cpu_generation_old` | Intel < 8-го поколения, AMD < Ryzen 2000 | info |
| `os_updates_stale` | последнее обновление > 60 дней | warning |
| `volume_free_low` | свободно на C < 15 % | warning |
| `drivers_old` | драйвер сети/видео старше 3 лет | info |

Даты, которые не удалось разобрать (нестандартная локаль), правило
молча пропускает — не выдумывает замечаний.

## Таблицы источников

`rules/data/os_lifecycle.json` и `rules/data/cpu_generations.json`
содержат `source_url` и `checked` (дата сверки). Значения сверены с
официальных страниц 2026-10-24:

- Windows 10: окончание поддержки 2025-10-14 — [support.microsoft.com](https://support.microsoft.com/en-us/windows/deployment/updates-lifecycle/windows-10-support-has-ended-on-october-14-2025);
- Windows 11 (канал Home/Pro: 24 месяца; Enterprise/Education: 36):
  23H2 → 2025-11-11, 24H2 → 2026-10-13, 25H2 → 2027-10-12,
  26H2 → 2028-10-10; Enterprise 23H2 → 2026-11-10, 24H2 → 2027-10-12 —
  [Windows 11 release information](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information);
- Минимальные CPU для Windows 11: Intel 8-го поколения+, AMD Ryzen
  2000+ — [Windows 11 specifications](https://www.microsoft.com/en-us/windows/windows-11-specifications).

## Прогноз заполнения диска

`rules/forecast.go`: линейная регрессия методом наименьших квадратов
по дневным точкам занятого места за последние 30 дней
(`disk_history`, миграция 9; одна точка на том/день, последний отчёт
дня побеждает).

Формула: по точкам `(x_i, y_i)` (x — номер дня от первой точки,
y — занято байт):

```
slope     = (n·Σx·y − Σx·Σy) / (n·Σx² − (Σx)²)
intercept = (Σy − slope·Σx) / n
R²        = 1 − Σ(y − ŷ)² / Σ(y − ȳ)²
```

- точек меньше **7** или **R² < 0,5** → прогноз не выдаётся
  (`insufficient_data`: «мало точек», «данные шумные»);
- наклон ≤ 0 → не переполнится (`days_to_full` отсутствует);
- иначе `days_to_full = ⌈(ёмкость − занято сейчас) / slope⌉`.

Пример: точки 1600, 1700, …, 2200 (7 дней, ровно +100/день) при
ёмкости 2600 → наклон 100/день, R² ≈ 1, `days_to_full = 4`.

Прогноз не «знает» будущих установок программ — это линейная оценка
по факту; при скачке занятого места R² падает и прогноз честно
исчезает до накопления новых точек.

## API

| Маршрут | Ответ |
|---------|-------|
| `GET /api/computers` | сводка: хост, статус, счётчики замечаний, максимальный приоритет, «заполнится через N дней» (минимум по томам) |
| `GET /api/computers/{id}` | карточка: инвентарь v1, замечания, прогнозы по томам |
| `GET /api/disks` | все тома всех агентов: занято/свободно, прогноз |

Без отчёта агента — «нет данных». Правила не настроены (нет движка) —
503.

## Переопределение

```
netatlas-server ... --rules-dir /etc/netatlas/rules
```

Каталог должен содержать все три файла (`rules.json`,
`os_lifecycle.json`, `cpu_generations.json`); в нём же можно
поправить пороги под площадку. Проверка переопределения покрыта
тестом.
