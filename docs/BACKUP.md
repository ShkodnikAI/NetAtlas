# Резервное копирование и восстановление

## Порядок копирования

1. Сервер может продолжать работать: `Backup` использует
   `VACUUM INTO`, копия консистентна независимо от параллельных
   транзакций (WAL учитывается автоматически).
2. Скопируйте базу в новый файл: в API появится вызов в NR-004/NR-005;
   до тех пор используется метод `store.Backup(ctx, path)` из
   отдельной утилиты.
3. Путь копии должен не существовать: `VACUUM INTO` и хранилище
   отказываются перезаписывать существующий файл
   (`store.ErrBackupExists`) — повторный вызов с тем же путём
   безопасен для данных, но ничего не сохранит.
4. Проверка копии: откройте её через `store.Open(копия)` и вызовите
   `audit.Verify` — цепочка журнала аудита должна совпасть.

## Порядок восстановления

1. Остановите сервер (`netatlas-server`), чтобы база не менялась.
2. Замените файл базы копией (переименуйте: копия должна стать
   основным файлом с тем же путём, что указан в `--db`). Файлы
   `-wal` и `-shm` старой базы удалите: они относятся к старому
   состоянию и несовместимы с восстановленной копией.
3. Запустите сервер. Миграции применятся автоматически: копия уже
   содержит таблицу `schema_version` с версией, повторных изменений
   не будет.
4. Сразу после запуска вызовите `audit.Verify`: если цепочка
   повреждена, копия недостоверна — восстановите более раннюю копию.

## Откат миграций

Отката миграции вниз средствами хранилища нет: миграции только
вперёд. Версия откатывается восстановлением резервной копии,
сделанной до применения версии.

| Версия | Что добавляет | Откат |
|--------|---------------|-------|
| 1 | Таблицы: `devices`, `device_ips`, `device_names`, `observations`, `links`, `scans`, `audit_log`, `schema_version` | Восстановить копию до версии 1 (пустая база): данных не было |
| 2 | Триггер `audit_log_no_update` (запрет правки журнала) | Восстановить копию до версии 2; запрещать правку при откате нельзя — это ослабление защиты |
| 3 | Триггер `audit_log_no_delete` (запрет удаления из журнала) | Восстановить копию до версии 3; запрещать удаление при откате нельзя — это ослабление защиты |
| 4 | Типы ручных элементов (расширение CHECK `kind`, NR-022) | Восстановить копию до версии 4 |
| 5 | Оповещения о новых неизвестных устройствах, таблица `alerts` (NR-005) | Восстановить копию до версии 5 |
| 6 | Хосты без MAC: значение `host` в CHECK `kind` (NR-023) | Восстановить копию до версии 6 |

Миграции 4 и 6 пересоздают таблицу `devices` вне транзакции: сбой
между DROP и RENAME восстанавливается из резервной копии, сделанной
до применения версии.
