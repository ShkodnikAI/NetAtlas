# Агент Windows: установка, сбор инвентаря, отзыв (NR-006)

Служба `NetAtlasAgent` регистрируется на сервере и раз в интервал
присылает инвентарь железа и ПО. **Ничего не исполняет и ничего не
меняет**: заданий в этом наряде нет. Агент сам инициирует соединения
(mTLS, TLS 1.3) и **не открывает ни одного слушающего порта** — это
проверяется тестом исходников (`TestAgentSourceOpensNoListeners`).

## Установка

Всё выполняется на машине агента. Сервер должен быть запущен с
агентскими слушателями (см. docs/AGENTS.md) и ключами PKI.

1. Выдать токен регистрации (порт владельца):

   ```
   curl -X POST -H "Authorization: Bearer $NETATLAS_TOKEN" ^
     http://127.0.0.1:8484/api/agents/enrollment
   ```

   Токен живёт 1 час и одноразовый. Скопировать `ca.pem` из каталога
   ключей сервера на машину агента (по защищённому каналу).

2. Зарегистрировать агента (адрес — слушатель регистрации сервера):

   ```
   netatlas-agent enroll --server https://server:8444 ^
     --token <ТОКЕН> --ca ca.pem
   ```

   Агент создаёт каталог состояния `%ProgramData%\NetAtlas\agent\`,
   генерирует ключ ECDSA P-256, отправляет CSR и получает сертификат.
   **Токен не сохраняется и не логируется** — это проверяется тестом
   (`assertTokenNotOnDisk`).

3. Установить службу (права администратора):

   ```
   netatlas-agent install --server https://server:8443
   ```

   Служба создаётся **остановленной** с автоматическим стартом при
   загрузке, учётная запись — виртуальная `NT SERVICE\NetAtlasAgent`.
   Стартует её владелец (всё включается вручную):

   ```
   sc start NetAtlasAgent      (или перезагрузка машины)
   netatlas-agent status       → running
   ```

4. Удаление:

   ```
   netatlas-agent uninstall    (права администратора)
   ```

## Что собирается (только чтение)

Отчёт версии 1 (`inventory_schema_version: 1`), каждые 15 минут
(интервал может скорректировать сервер в ответе `checkin`):

| Блок | Поля |
|------|------|
| ОС | выпуск, версия, сборка, архитектура, время загрузки; обновления (KB, описание, дата), дата последнего обновления |
| Железо | процессоры (имя, ядра/потоки, частота); ОЗУ (общий объём, слоты: объём/частота/производитель); материнская плата; BIOS (версия, дата) |
| Диски | физические диски (модель, серийник, тип, объём, здоровье); износ и температура SSD — если диск отдаёт счётчики (`Get-StorageReliabilityCounter`), иначе поля отсутствуют; тома (буква, метка, ФС, объём, свободно) |
| Сеть | адаптеры (имя, описание, MAC, скорость линка, состояние, IPv4) |
| Драйверы | устройство, производитель, версия, дата (`Win32_PnPSignedDriver`) |
| Программы | имя, версия, издатель, дата установки (ключи `Uninstall` реестра, включая WOW6432Node и HKCU) |

Сценарии PowerShell **встроены в бинарь** (`go:embed`), запускаются с
фиксированными флагами `-NoProfile -NonInteractive -ExecutionPolicy
Bypass -Command`; текст из сети в команду не попадает никогда. Ошибки
сборщиков не роняют службу — попадают в `collector_errors` отчёта.

## Что НЕ собирается

Ничего об активности пользователей: история браузера, нажатия,
содержимое файлов, скриншоты, переписка, пароли (в любом виде),
геолокация, история посещённых адресов. Сетевые данные ограничены
MAC/IPv4/скоростью линка адаптеров. Список полей отчёта закрыт схемой
версии 1: сервер отклоняет лишнее строгим разбором JSON.

## Потеря связи

Отчёты буферизуются в `%ProgramData%\NetAtlas\agent\spool` (не больше
20 МБ суммарно, самое старое вытесняется), по восстановлении связи
уходят по порядку; паузы повторов растут от 30 секунд до 15 минут.
Записи очереди удаляются только после подтверждения сервера
(at-least-once).

## Проверка прав на ключ

Каталог и закрытый ключ доступны только SYSTEM и администраторам;
права выставляются программно при создании (`icacls`, наследование
снято). Проверить вручную:

```
icacls "%ProgramData%\NetAtlas\agent\agent.key"
```

Ожидается: `SYSTEM:(F)` и `BUILTIN\Administrators:(F)`, строка
`Ходнаследовано`/`Inherited` отсутствует, доступ «Пользователи»/
`Users` не выдан. На каталоге аналогично с `(OI)(CI)F`.

## Отзыв агента

На сервере (порт владельца):

```
curl -X POST -H "Authorization: Bearer $NETATLAS_TOKEN" ^
  http://127.0.0.1:8484/api/agents/<agent_id>/revoke
```

Либо отзыв сертификата: `netatlas-pki revoke <serial>`. Следующее
подключение отозванного агента отвергается на handshake (кэш списка
отзыва до 10 секунд), отказы видны в `GET /api/audit`
(`agent_checkin/deny`). На машине агента — `netatlas-agent uninstall`.

## Что агент не делает

- не принимает и не исполняет задания (появятся в NR-012/NR-013 и
  будут включаться владельцем отдельно);
- не открывает портов, не слушает сокеты;
- не пишет ничего вне своего каталога состояния и реестра службы.

## Сценарий для владельца (Hyper-V, живой прогон)

Тесты CI проверяют логику и реальный сбор на windows-latest. Живой
прогон с потерей связи — вручную:

1. Поднять сервер с агентскими слушателями и выдать токен.
2. Создать ВМ Hyper-V с Windows 10/11, поставить `netatlas-agent`
   (шаги 1–3 раздела «Установка»), запустить службу.
3. Убедиться: `GET /api/agents` показывает агента; устройства из его
   MAC-списка получили класс `managed`; `GET
   /api/agents/<id>/inventory` возвращает отчёт версии 1.
4. **Потеря связи**: выключить сетевой адаптер ВМ (или остановить
   сервер) на 20 минут, затем руками выполнить на ВМ
   `netatlas-agent run --once` с недоступным сервером — отчёт уйдёт в
   spool. Проверить `dir %ProgramData%\NetAtlas\agent\spool`.
5. Вернуть связь: очередь сливается по порядку, `GET
   /api/agents/<id>/inventory` отдаёт свежий отчёт, spool пуст.
6. Отозвать агента и убедиться, что следующий checkin отвергается, а
   в аудите появились записи `agent_checkin/deny`.
7. `netatlas-agent uninstall` — служба удалена, каталог можно
   удалить руками.
