# Принятые решения и инварианты

Документ для исполнителя и для аудита. Инварианты нельзя нарушать без явного решения владельца.

## Контекст

- Личная система владельца, не для продажи и внешнего использования.
- Парк: Windows-компьютеры, сетевое оборудование с SNMP (уточняется), возможны гостевые устройства без агента.
- Сервер: админский компьютер или постоянно включённое устройство (предпочтительно).

## Инварианты безопасности

1. **Изоляция ИИ.** Зона ИИ принимает только текст отчёта и возвращает только текст. У неё нет ключей, учётных данных, сетевого доступа к агентам, серверу управления и репозиторию скриптов. Ответ ИИ всегда считается предложением, а не командой.
2. **Недоверенные данные.** Логи и любой текст из сети считаются недоверенными и могут содержать попытки внедрить инструкции.
3. **Очистка перед отправкой ИИ.** Имена и адреса заменяются псевдонимами, пароли, токены и ключи вырезаются, учётные записи скрываются. Таблица соответствий остаётся только у владельца.
4. **Подпись заданий.** Агент выполняет только задания, подписанные ключом сервера. Подпись ставится только после статуса «протестирован» и подтверждения владельца.
5. **Канал связи.** Агент сам подключается к серверу, взаимная проверка сертификатов (mTLS), входящие порты на компьютерах не открываются.
6. **Каталог действий.** Типовые операции оформляются как проверенные шаблоны с параметрами. Произвольный скрипт отдельное право доступа.
7. **Журнал аудита.** Каждое действие записывается: кто, когда, что, на какой цели, результат.
8. **Откат.** Перед изменениями создаются точки восстановления, результат измеряется «до/после», при отсутствии улучшения изменение откатывается.
9. **Дефолты тихого режима.** Служба без окон допустима, но уведомление пользователя, окна обслуживания и отложенная перезагрузка настраиваются.

## Конвейер скрипта

1. Черновик (в том числе из рекомендации ИИ)
2. Статическая проверка (PSScriptAnalyzer для PowerShell) и пробный режим (`-WhatIf`)
3. Тест на виртуальной машине Hyper-V по снимку-эталону
4. Подпись владельца
5. Один реальный компьютер и сравнение метрик
6. Раскатка на группу

Ограничение: виртуальная машина не воспроизводит физическое железо. Для драйверов, сетевых карт и устройств этап 5 обязателен.

## Сбор данных об активности сотрудников

- Собирается: активное приложение и время в нём, домены сайтов, время активности и простоя, только на рабочих компьютерах.
- Не собирается: нажатия клавиш, содержимое писем и переписки, пароли, полные адреса страниц. Скриншоты выключены.
- Учётная запись администратора исключена.
- Хранение 90 дней, доступ только владельцу.
- Перед включением сотрудников письменно уведомляют. Порядок зависит от законодательства страны, требуется уточнение владельцем.

## Классы устройств

| Класс | Источник данных | Возможности |
|---|---|---|
| Управляемый (агент) | Агент + безагентные источники | Полный аудит, исполнение действий |
| Известное без агента | Сканирование, SNMP, DHCP | Присутствие, трафик, порт, базовые свойства |
| Гость | Сканирование, Wi‑Fi, DHCP | Присутствие и трафик, без тревог |
| Неизвестное | Сканирование | Оповещение и разбор владельцем |

Активное сканирование ограничивается по скорости. Чужие гостевые устройства глубоко не сканируются.

## Открытые вопросы

- Модели коммутаторов, роутера и точки Wi‑Fi (поддержка SNMP, списка клиентов, счётчиков)
- Число подсетей и VLAN, наличие отдельной гостевой сети
- Расположение сервера (админский ПК или отдельное устройство)
- Облачный ИИ с обезличиванием или локальная модель
- Правовой порядок уведомления сотрудников
- Редакция Windows на админском ПК (для Hyper-V нужна Pro или выше)
