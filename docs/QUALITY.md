# Качество сети: измерения, хранение, правила (NR-008)

## Что измеряется

**Агент** (лёгкие замеры раз в 5 минут, входят в цикл `run`):

| Метрика | Как | Цель |
|---------|-----|------|
| `latency`, `jitter`, `loss` | серия из 20 ICMP-эхо (`IcmpSendEcho`, прав админа не нужно); джиттер — стандартное отклонение разностей соседних RTT; потери — доля несостоявшихся | шлюз (по таблице маршрутов), сервер |
| `dns` | время разрешения имени сервера | DNS-резолвер системы |
| `tcp` | время TCP-соединения | сервер |

**Тяжёлые замеры — только в окне простоя 01:00–05:00 локального времени:**

| Метрика | Как |
|---------|-----|
| `down_mbps` / `up_mbps` до сервера | `GET /agent/v1/blob?bytes=N` и `POST /agent/v1/blob` (не больше 8 МБ) |
| `down_mbps` интернета | загрузка с `speed_url` — **по умолчанию пусто = выключено**, задаёт владелец |
| `bufferbloat` | задержка до шлюза во время загрузки против покоя (разница в мс) |

Агент **не принимает входящих соединений**, поэтому замеров «агент → агент» нет: матрица строится как «агент × цель» (шлюз, сервер, DNS, интернет) плюс счётчики SNMP коммутаторов. Это зафиксированное решение аудитора.

**Сервер (SNMP)**: при явных `--snmp-targets` (адреса, только внутри `--subnets`, учётные данные из `NETATLAS_SNMP_*`, только чтение) читает `ifInOctets/ifOutOctets/ifInErrors/ifOutErrors/ifInDiscards/ifHighSpeed` раз в 5 минут и считает загрузку порта по разности с учётом переполнения 32-битного счётчика. Первая точка — база разностей.

## Лимиты (замеры не влияют на работу)

- объём: не больше **20 МБ в сутки на агента** (счётчик обнуляется в 00:00 локального; тяжёлые замеры пропускаются при исчерпании, лёгкие продолжаются);
- расписание: лёгкие раз в 5 минут, тяжёлые только 01:00–05:00;
- остановка замеров при загрузке **CPU выше 70 %** или сети **выше 50 % канала** (состояние машины — встроенный PS-сценарий: `Win32_Processor.LoadPercentage`, дельта счётчиков адаптеров за секунду против скорости линка).

Сравнение с порогами: ровно порог — не замечание (проверено тестами).

## Хранение и уплотнение

| Уровень | Гранулярность | Хранится |
|---------|---------------|----------|
| сырые значения | как пришли | 48 часов |
| агрегаты 5 минут | среднее, p95, максимум, число потерь | 30 суток |
| агрегаты час | то же | 1 год |

Фоновая задача сервера уплотняет раз в час: сырые старше 48 часов → 5-минутные окна (UTC), 5-минутные старше 30 суток → часовые, старше года — удаляется. Уплотнение идемпотентно: повторный запуск в те же окна перезаписывает те же значения (`INSERT OR REPLACE`), ничего не удваивая. p95 по отсортированному ряду окна.

## Правила узких мест (`rules/data/network.json`)

| Правило | Порог | Серьёзность |
|---------|-------|-------------|
| `loss_high` | потери > 2 % | warning |
| `loss_very_high` | потери > 5 % | critical |
| `gateway_latency_high` | задержка до шлюза > 50 мс | warning |
| `jitter_high` | джиттер > 30 мс | warning |
| `port_util_high` | загрузка порта > 80 % в среднем за час | warning |
| `port_errors` / `port_discards` | ошибки/отбросы растут | warning |
| `bufferbloat_high` | > 100 мс | warning |

## API и экран

| Маршрут | Ответ |
|---------|-------|
| `GET /api/quality/matrix` | агент × цель: последние значения, состояние |
| `GET /api/quality/series?agent=&target=&kind=&from=&to=&hourly=1` | ряд агрегатов (часовые — для графика за сутки) |
| `GET /api/quality/bottlenecks` | узкие места всех агентов |

Экран «Качество сети»: матрица («нет данных» для выключенных узлов), график скорости за сутки (среднее/p95/макс), список узких мест с рекомендациями.

## Как отключить / включить

- замеры агента: не включаются вообще, если агент запущен без них (флаг замеров — на стороне запуска агента; по умолчанию выключены);
- интернет-скорость: не задавать `speed_url`;
- SNMP: не задавать `--snmp-targets` (задача не запускается).

## Сценарий для владельца (живой прогон, ВМ)

Эмуляцию задержек и потерь в тестах нет — проверяется вручную:

1. Поднять сервер с `--snmp-targets` (коммутатор в подсети) и агента с замерами.
2. Убедиться: `GET /api/quality/matrix` показывает ячейки агента; в `GET /api/quality/bottlenecks` пусто на спокойной сети.
3. В ВМ агента включить загрузку канала (например, скачивание) — `port_util_high`/`bufferbloat_high` появляются в узких местах, график за сутки показывает рост.
4. Проверить уплотнение: вставить сырые точки старше 48 часов (SQL) — после часового тика они уходят в 5-минутные агрегаты, `metrics_raw` сокращается.
5. Вернуть сеть в норму — узкие места исчезают.
